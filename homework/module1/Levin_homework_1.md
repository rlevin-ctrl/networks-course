# Домашнє завдання до 1-го змістовного модуля

**Тема:** Основи комп'ютерних мереж

---

## Завдання 1. Дослідження мережі

**Виконана команда:** `ip a`

**Результат команди (фрагмент основного інтерфейсу):**

```text
2: enp0s3: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500 qdisc fq_codel state UP group default qlen 1000
    link/ether 08:00:27:65:a1:94 brd ff:ff:ff:ff:ff:ff
    inet 192.168.1.14/24 brd 192.168.1.255 scope global dynamic noprefixroute enp0s3
       valid_lft 86120sec preferred_lft 86120sec
```
<img width="875" height="578" alt="Screenshot 2026-10-18 204550" src="https://github.com/user-attachments/assets/7c79d8b1-0d6d-404b-9833-ae5ffc89253d" />

### Аналіз даних

- **Інтерфейс:** `enp0s3` — основний мережевий адаптер, Ethernet.
- **Тип підключення:** дротове (Ethernet) через NAT у VirtualBox. Адреса отримана динамічно через DHCP.
- **MAC-адреса:** `08:00:27:65:a1:94` — належить віртуальній машині VirtualBox. Відповідає канальному рівню (L2).
- **IP-адреса:** `192.168.1.14` — належить мережевому рівню моделі OSI (L3, Network).
- **Маска підмережі:** `/24` або `255.255.255.0` — належить мережевому рівню моделі OSI (L3, Network).
- **Gateway (шлюз):** `192.168.1.1` — визначено з команди `ip r`.
- **Broadcast-адреса:** `192.168.1.255`.
- **Діапазон хостів:** `192.168.1.1 – 192.168.1.254` (всього 254 адреси).

> **Примітка:** у виводі також присутні інтерфейси Docker — `docker0` та `br-...`. Вони є віртуальними внутрішніми мережами і не використовуються для виходу в інтернет.

## Завдання 2. Дослідження маршрутизації

**Виконана команда:** `ip r`

**Результат команди:**

```text
default via 192.168.1.1 dev enp0s3 proto dhcp src 192.168.1.14 metric 100 
172.17.0.0/16 dev docker0 proto kernel scope link src 172.17.0.1 linkdown 
172.18.0.0/16 dev br-ec45c2f2f129 proto kernel scope link src 172.18.0.1 
192.168.1.0/24 dev enp0s3 proto kernel scope link src 192.168.1.14 metric 100
```
<img width="786" height="133" alt="Screenshot 2026-10-18 205656" src="https://github.com/user-attachments/assets/3a59a773-0529-44a8-911e-148d53c488ae" />

### Аналіз

- **Протокол, через який отримано IP:** `dhcp` — Dynamic Host Configuration Protocol.
- Це видно з рядка маршруту за замовчуванням:

  ```text
  default via 192.168.1.1 dev enp0s3 proto dhcp
  ```

- Це означає, що IP-адреса та адреса шлюзу були автоматично видані DHCP-сервером (роутером), а не налаштовані вручну.

## Завдання 3. Знаходження публічної IP-адреси

**Виконана команда:** `curl ifconfig.io`

**Результат:** отримано публічну IP-адресу (приховано з міркувань безпеки: `x.x.x.x`).
<img width="469" height="47" alt="5958737803300507709" src="https://github.com/user-attachments/assets/a31d2cb5-2600-4ecb-8f89-486f066aec32" />

### Порівняння локальної та публічної адрес

| Тип адреси | Значення | Призначення |
|---|---|---|
| Локальна IP-адреса | `192.168.1.14` | Ідентифікація комп'ютера в домашній локальній мережі |
| Публічна IP-адреса | `x.x.x.x` | Адреса, видима в глобальному інтернеті |

**Чи однакові адреси?** Ні, вони різні.

### Чому вони різні?

Домашній роутер виконує функцію **NAT** (*Network Address Translation* — перетворення мережевих адрес). Провайдер виділяє роутеру лише одну публічну IP-адресу, яка є видимою в глобальному інтернеті.

Всім пристроям у локальній мережі — комп'ютерам, телефонам тощо — роутер роздає приватні IP-адреси з діапазону `192.168.x.x` через DHCP.

Коли комп'ютер надсилає запит в інтернет, роутер підмінює приватну адресу на свою публічну. Тому сайт `ifconfig.io` бачить лише IP-адресу роутера, а не локальну адресу комп'ютера.

Це забезпечує:

- безпеку локальних пристроїв;
- економію публічних IPv4-адрес у світі.
